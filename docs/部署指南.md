# 部署指南

本系統由「**前端靜態網站**（GitHub Pages）」+「**Google Apps Script 後端**（讀取 Drive 清冊）」兩部分組成。

---

## Part 1：Google Drive 清冊資料夾

### 1.1 建立資料夾

1. 登入 Google 雲端硬碟
2. 建立資料夾（建議命名：`OSHA_補考清冊`）
3. 把所有 `結訓測驗報名清冊_*.xlsx` 檔案上傳進去
4. 從網址列複製資料夾 ID：
   ```
   https://drive.google.com/drive/folders/【這串就是 ID】
   ```

### 1.2 清冊格式要求

清冊必須符合既有「結訓測驗報名清冊」格式：

| 列 | 內容 |
|----|------|
| 1  | 標題：結訓測驗報名清冊 |
| 2  | 訓練單位：__代碼 名稱__ |
| 3  | 訓練種類：__代碼+名稱__（例 `07040缺氧作業主管...`） |
| 4  | 測驗試場：__代碼 名稱__ |
| 5  | 測驗年度：__民國年__（例 `115`） |
| 6  | 梯次：__數字__（例 `04`） |
| 7  | 欄位名稱列：序號 / 期別 / 姓名 / 身分證統編 / 出生日期 / 郵遞區號 / 聯絡地址 / 電話 / 學歷 / 開訓日 / 結訓日 / 主管機關備查文號 |
| 8+ | 應試者資料 |

> 同一資料夾內可放多份不同梯次的清冊，系統會自動全部合併。

## Part 2：Google Apps Script 後端

### 2.1 建立 Apps Script 專案

1. 開 https://script.google.com/
2. 「新增專案」→ 命名（例 `OSHA-Roster-API`）
3. 把 [`tools/gas_backend.js`](../tools/gas_backend.js) 完整內容覆蓋到 `Code.gs`

### 2.2 啟用 Drive Advanced Service

讀取 .xlsx 必須啟用此服務：

1. 左側「服務」（Services）→ 點 `+`
2. 選擇 **Drive API**（識別碼保持 `Drive`，版本 `v2`）
3. 點「新增」

### 2.3 修改設定常數

編輯 Code.gs 頂部：

```javascript
const API_TOKEN = 'OSHA_USER_<請改成隨機字串>';   // 改成你的隨機字串
const ROSTER_FOLDER_ID = '__請填入 Drive 資料夾 ID__';    // 步驟 1.1 取得的 ID
```

> **建議**：`API_TOKEN` 用一段隨機字（20 字以上），不要與其他系統共用。

### 2.4 測試後端

1. 在編輯器頂部選 `_testLoadRosters` → 「執行」
2. 第一次會跳「需要授權」→ 點通過 → 「進階」→「前往專案」→ 允許
3. 執行紀錄應顯示 `總筆數: XX` 與第一筆資料

### 2.5 部署為網頁應用程式

1. 右上「部署」→「新增部署」
2. 類型：**網頁應用程式**
3. 設定：
   - 說明：`v1`
   - 執行身分：**我**（即你的 Google 帳號）
   - 存取權：**任何人**
4. 點「部署」→ 複製「網頁應用程式 URL」（結尾是 `/exec`）

### 2.6 驗證

```bash
curl 'https://script.google.com/macros/s/.../exec?token=YOUR_TOKEN&action=ping'
# 應回傳 {"ok":true,"time":"2026-04-15T..."}

curl 'https://script.google.com/macros/s/.../exec?token=YOUR_TOKEN&action=roster'
# 應回傳 {"records":[...],"cached":false}
```

## Part 3：前端設定

編輯 `js/config.js`：

```javascript
window.APP_CONFIG = {
  GAS_URL: 'https://script.google.com/macros/s/.../exec',  // 步驟 2.5 取得
  API_TOKEN: 'OSHA_USER_<請改成隨機字串>',           // 與 GAS 一致
  // ... 其他保留預設
};
```

## Part 4：GitHub Pages 部署

### 4.1 建立 repo 並推送

```bash
cd "管理職類測驗補考報名表"
git init
git branch -M main
git add .
git commit -m "feat(初始化): 建立補考報名表系統"
git remote add origin https://github.com/<你的帳號>/<repo-name>.git
git push -u origin main
```

### 4.2 啟用 Pages

1. GitHub repo → Settings → Pages
2. Source 選 `Deploy from a branch`
3. Branch 選 `main` / `(root)`
4. Save

幾分鐘後系統會給你網址：`https://<帳號>.github.io/<repo>/`

### 4.3 升級時

1. 修改檔案後 `git push`
2. 改 `js/config.js` 的 `VERSION` 與 `sw.js` 的 `CACHE_NAME` （例 `20260420a`）
3. 把 HTML 中的 `?v=` query 也同步更新

## 故障排除

| 症狀 | 可能原因 | 處理 |
|------|---------|------|
| 清冊載入失敗 / unauthorized | API_TOKEN 不一致 | 確認前後端 token 完全相同 |
| `Drive is not defined` | 未啟用 Advanced Drive Service | 步驟 2.2 重做 |
| 找不到清冊資料夾 | FOLDER_ID 錯誤或無讀取權限 | 確認 ID 正確、執行身分有讀取權 |
| GAS 回應慢（10 秒以上） | 第一次轉換 .xlsx 較慢 | 後續會由 CacheService 快取 1 小時 |
| 列印超過一頁 | 內容過長或字級過大 | 編輯 `css/print.css` 縮小 padding/字級 |
| 前端改了沒生效 | Service Worker 快取 | 改 `sw.js` 的 `CACHE_NAME` 觸發更新 |

## 安全強化建議（選做）

GAS 雖有 `API_TOKEN` 防護，但 token 暴露在前端原始碼中。生產環境可加：

1. **網域白名單**（在 `doGet` 開頭）：
   ```javascript
   const referer = e.parameter.referer || '';
   if (!referer.includes('github.io') && !referer.includes('localhost')) {
     return jsonResp({ error: 'forbidden origin' });
   }
   ```
2. **IP / UA Rate limit**（參考既有 exam-site 的 `gas_backend.js` 實作）
3. **僅返回必要欄位**：剔除電話/地址等敏感資訊到前端，列印頁臨時補回
