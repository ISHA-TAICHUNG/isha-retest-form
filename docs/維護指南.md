# 維護指南

日常維護常見動作與標準流程。

---

## 1. 上傳新梯次清冊

**情境**：協會新增一份梯次清冊（例 `結訓測驗報名清冊_05201500.xlsx`）。

**步驟**：

1. 上傳 .xlsx 到 Google Drive 設定的清冊資料夾（不需重新部署）
2. 開首頁 → 點「**重新載入清冊（強制刷新）**」
3. 完成 ✓

> 若使用者反映查不到，多半是前端 sessionStorage 或 GAS Cache 未刷新 → 點「強制刷新」即可。

---

## 2. 新增或修改測驗職類

**情境**：trains.osha.gov.tw 新增了某職類，下拉選單沒列出。

**步驟**：

1. 開 [`js/job-categories.js`](../js/job-categories.js)
2. 在對應分類下加一筆物件：
   ```javascript
   { code: '07090', name: '新增的職類名稱', group: '特殊作業主管' },
   ```
3. 升版本號（見下方流程 §5）
4. `git commit + push`

---

## 3. 變更訓練單位 / 主管機關等固定欄位

**情境**：協會搬家、主管機關文號格式調整。

**步驟**：

1. 開 [`js/config.js`](../js/config.js)
2. 修改對應常數（`TRAINING_UNIT` / `AUTHORITY` / `TEST_VENUE`…）
3. 升版本號
4. `git commit + push`

---

## 4. 微調 A4 列印版面

**情境**：列印超出 1 頁、某欄位文字被切掉、字級需要再緊一點。

**步驟**：

1. 開 [`css/print.css`](../css/print.css)
2. 常見調整：

   | 想要 | 修改處 |
   |------|--------|
   | 整體縮小一點 | 調 `.print-page { font-size }`，預設 10pt |
   | 行距更緊 | 調 `.print-page { line-height }`，預設 1.25 |
   | 表格 padding 更小 | 調 `.print-table th, .print-table td { padding }`，預設 `2px 4px` |
   | 身分證影本欄變大/小 | 調 `.id-cell { height }`，預設 3.6cm |
   | 標題字級 | 調 `.print-title { font-size }`，預設 15pt |
   | 邊界 | 調 `@page { margin }`，預設 `0.8cm 1cm` |

3. **驗證**：
   - 開 print.html
   - 瀏覽器 `Ctrl/Cmd + P` 預覽
   - 確認所有內容在 1 頁 A4 內
4. 升版本號 + push

---

## 5. 升版本號流程

CSS/JS 修改後，務必同步更新 3 處版本號讓使用者瀏覽器能拿到新檔：

### 5.1 `js/config.js`
```javascript
VERSION: '20260415a',  // 改為當天日期+字母（例 20260420a）
```

### 5.2 `sw.js`
```javascript
const CACHE_NAME = 'osha-form-v20260415a';  // 同上日期
// 並更新 STATIC_ASSETS 陣列中所有 ?v= 參數
```

### 5.3 三個 HTML 檔的 `?v=` query
- `index.html`
- `form.html`
- `print.html`

全部把 `?v=20260415a` 替換為新版本號。

> 💡 **快速做法**：用編輯器全專案搜尋取代 `20260415a` → 新版本號。

---

## 6. GAS 後端升級

**情境**：修改 `tools/gas_backend.js`（例如新增解析欄位、調整 cache TTL）。

**步驟**：

1. 編輯 `tools/gas_backend.js`（本地 git 紀錄用）
2. 複製內容到 https://script.google.com 對應專案的 `Code.gs`
3. **重要**：右上「部署」→「**管理部署**」→ 找到現有部署 → 鉛筆圖示 → 版本選「**新版本**」→ 部署
   - 不要點「新增部署」（會產生新 URL，前端要重設）
4. （可選）首頁強制刷新清冊驗證新邏輯

---

## 7. 修改 GAS 安全設定（更換 token）

**步驟**：

1. 同時修改：
   - GAS `Code.gs` 頂部的 `API_TOKEN`
   - 前端 `js/config.js` 的 `API_TOKEN`
2. GAS 重新部署（流程 §6）
3. 前端 push（流程 §5）
4. 提醒所有使用者按「強制刷新」

---

## 8. 備份策略

**前端**：GitHub 即備份。建議定期 tag 穩定版本：
```bash
git tag -a v1.0.0 -m "首版上線"
git push --tags
```

**GAS 後端**：每次部署會自動保留版本，可在「管理部署」回滾到舊版。

**清冊**：Google Drive 自動版本歷史，誤刪可在垃圾桶救回 30 天。

---

## 9. 監控與偵錯

### 前端錯誤
- 開瀏覽器 DevTools (F12) → Console 看錯誤訊息
- 常見：`Failed to fetch` → GAS_URL 錯誤或 CORS 問題

### GAS 後端執行紀錄
- https://script.google.com/ → 對應專案 → 左側「執行作業」(Executions)
- 看每次 doGet 的執行時間、錯誤訊息

### Service Worker 卡住
- DevTools → Application → Service Workers → Unregister
- 重新整理頁面

---

## 10. 緊急回滾

**前端**：
```bash
git revert HEAD       # 撤銷最近一次 commit
git push
```

**GAS 後端**：
- 「管理部署」→ 編輯 → 版本選舊版本 → 部署

**清冊**：
- Drive → 右鍵檔案 → 「版本記錄」→ 還原舊版

---

## 附錄：版本號慣例

格式：`YYYYMMDDx`，例 `20260415a`
- `YYYYMMDD`：當日日期
- `x`：當天的修改序號 (a, b, c, …)，避免同天多次更新時瀏覽器仍拿到舊檔

範例：
- `20260415a` — 2026/04/15 第一次更新
- `20260415b` — 2026/04/15 第二次更新（小修補）
- `20260420a` — 2026/04/20 新功能上線
