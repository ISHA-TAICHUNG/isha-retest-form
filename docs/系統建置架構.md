# 職業安全衛生測驗補考線上報名系統 — 建置架構文件

> 開源架構參考，適用於各訓練單位自行部署。本文不含任何單位特定資訊。

## 📝 文件慣例

- **Placeholder 格式**：本文一律用 `{單位名稱}` 大括號表示需填入的值
- **「本 repo」**：指由提供本文件的單位給你的原始 repo（請向他們索取網址）
- **「貴單位」**：指準備建置此系統的你

## 📋 系統定位

| 項目 | 內容 |
|------|------|
| **目標使用者** | 已結訓但需補考的學員（使用者技術背景多元，多以手機操作） |
| **核心情境** | 學員到櫃檯，用手機輸入身分證 → 自動帶資料 → 拍身分證 → 送出 |
| **預期負載** | 每天約 50-100 筆，每月 1000-2000 筆（若 > 1000 筆/日 建議升 Workspace 付費版以避免 GAS 配額限制） |
| **資料敏感度** | 含個資（姓名 / 身分證 / 電話 / 地址），需符合個資法 |

## 🏗 整體架構

```
┌─────────────────┐     ①查詢       ┌──────────────────┐
│  學員手機瀏覽器  │ ─────────────→ │   GitHub Pages   │
│  (iOS / Android) │ ←───────────── │   （靜態前端）   │
└──────────────────┘     HTML/JS    └──────────────────┘
        │
        │  ②身分證查詢
        │  ③送出 PDF
        ▼
┌──────────────────┐
│ Google Apps      │
│ Script Web App   │
│ (後端 API 閘道)  │
└──────────────────┘
        │
        ├──→ ④讀清冊 → Google Drive 資料夾（清冊 .xlsx）
        ├──→ ⑤讀行事曆 → Google Drive 試算表（考試日期）
        └──→ ⑥存報名表 → Google Drive 資料夾（PDF）
```

**為什麼選這套架構：**
- 🆓 **零基礎設施成本**：GitHub Pages 免費、Google Workspace 通常單位已有
- 🛠 **無需自建主機**：不用付伺服器費、不用維運
- 🔒 **資料留在 Google Drive**：與單位既有資料管理整合
- 📱 **PWA 體驗**：手機可加到主畫面，類 App 體驗

## 🎯 核心功能清單

### 學員端

1. **身分證查詢** — 輸入身分證號自動帶出所屬補考資料
2. **多筆紀錄選擇** — 同一人多筆報名時可選擇梯次
3. **資料微調** — 電話、地址、發票、考場等可修改
4. **身分證影本上傳**
   - 客製全螢幕相機（getUserMedia + 1.58:1 框）
   - 拍後裁切 Modal
   - 自動處理 EXIF orientation
   - 相簿 fallback
5. **預計開考日提示** — 依考場 / 月份自動帶入
6. **A4 PDF 預覽** — 即時 client-side 渲染
7. **一鍵送出** — 自動上傳 PDF 至訓練單位 Drive
8. **LINE 加好友引導** — 送出後自動跳轉

### 管理端（透過 Google Drive 操作）

1. **清冊管理** — 直接編輯 Drive 上的 xlsx，前端 1 小時內同步
2. **行事曆管理** — 同上，編輯 Google Sheet 即可
3. **報名表收件** — 自動分類於指定資料夾
4. **管理員 API** — 透過 ADMIN_TOKEN 可取全清冊 / 清快取

## 🔧 技術棧

### 前端
- **HTML / CSS / Vanilla JS**（無框架，純靜態檔案）
- **html2canvas 1.4.1** + **jsPDF 2.5.2** — 客戶端 PDF 生成
- **getUserMedia API** — 客製相機
- **createImageBitmap** — EXIF orientation 自動處理
- **Service Worker：本系統刻意不使用** — 改靠 HTTP cache（10 分鐘）+ `?v=` query string busting 達成版本更新，避免 PWA 卡舊版的常見問題

### 後端
- **Google Apps Script Web App**
- 使用 `DriveApp` / `SpreadsheetApp` / `CacheService`
- 部署為「以我身分執行 + 任何人可存取」

### 儲存

  - 清冊資料夾（學員報名清冊 .xlsx，多份自動合併）
  - 考試行事曆（Google Sheet 或 .xlsx）
  - 報名表收件資料夾（學員送出的 PDF）

### 部署
- **GitHub Pages**（前端託管）
- **GitHub Actions** + `actions/deploy-pages` workflow
- **clasp**（GAS 程式碼版本控制）

## 🔒 安全設計（四層防禦）

```
┌─────────────────────────────────────────┐
│  第 1 層：API_TOKEN（公開、初階鎖）     │
├─────────────────────────────────────────┤
│  第 2 層：Origin 白名單                 │
├─────────────────────────────────────────┤
│  第 3 層：Rate Limit（每分鐘 10 次）    │
├─────────────────────────────────────────┤
│  第 4 層：Lookup-only API（關鍵防線）   │
│  即使所有上層被繞過，每次只回 1 筆      │
│  攻擊者無法一次拉走全清冊               │
└─────────────────────────────────────────┘
```

### 重要原則
- ✅ **API_TOKEN 可公開**：靠 lookup-only 限制傷害
- ✅ **ADMIN_TOKEN 永不出 server**：存於 GAS ScriptProperties
- ✅ **清冊永不入 git**：`.gitignore` 鎖死 `data/` 與 `*.xlsx`
- ✅ **lookup 結果 PII minimization**：剔除內部欄位
- ✅ **PDF 寫入時驗證 magic number**：`%PDF` 確認真為 PDF
- ✅ **檔案大小上限**：10MB 防呆

## 🚀 部署步驟（給新單位的 SOP）

### 前置條件

開始前確認你有：

- ✅ 一個可登入 Google Apps Script 的 Google 帳號（建議用單位專用帳號，不要用個人帳號）
- ✅ 一個 GitHub 帳號（個人或組織帳號皆可）
- ✅ 一台能執行 `git` 與 `openssl`（或 PowerShell）的電腦
- ✅ 學員清冊 .xlsx 樣本一份（可先用 5-10 筆測試資料）
- ✅ 從上游取得的 source repo URL

### 第一階段：準備 Google 資源

1. **建立專用 Google 帳號**（或用既有單位帳號）
2. **建立兩個 Drive 資料夾**：
   - 清冊資料夾（放學員報名清冊）
   - 報名表收件資料夾（接收 PDF）
3. **取得兩個資料夾 ID**（URL 中 `folders/` 後的字串）
4. **上傳清冊範本到清冊資料夾**（.xlsx 格式）
5. **上傳考試行事曆**（檔名含「行事曆」三字，欄位至少含「考場」與「開考日」）

### 第二階段：建立 GAS 後端

1. 至 `script.google.com` 建立新專案
2. 把 `tools/gas_backend.js` 內容貼到 `Code.gs`
3. **啟用 Drive API**：GAS 編輯器左側「服務 (Services)」→ 點「+」→ 選「Drive API v3」→ 點「新增」
   - ⚠ 首次部署若跳出 OAuth「Google 尚未驗證此應用程式」警告，點「**進階 → 移至 (不安全)**」是正常流程（因為是你自己寫的程式）
4. **產生隨機 token**（用以下任一種方式）：
   - macOS / Linux：`openssl rand -hex 32`
   - Windows PowerShell：`-join ((48..57+65..90+97..122) | Get-Random -Count 64 | %{[char]$_})`
   - 線上產生器（不建議，會經第三方）：搜尋 "random hex 64 char"
5. 修改頂部設定區：
   ```js
   const API_TOKEN = '{剛產生的 64 字元字串}';
   const ROSTER_FOLDER_ID = '{清冊資料夾 ID}';
   const SUBMISSIONS_FOLDER_ID = '{報名表收件資料夾 ID}';
   const ALLOWED_ORIGINS = ['{你的帳號}.github.io'];
   ```
6. **Script Properties** 新增 `ADMIN_TOKEN`（另一組獨立的隨機字串，僅後端持有）：
   - 編輯器左下「Project Settings (專案設定)」→「Script Properties」→「Add script property」
   - Property：`ADMIN_TOKEN`、Value：再產一組新的隨機字串
7. **部署 → 新增部署 → 類型「網頁應用程式」**
   - 執行身分：**我**
   - 存取權：**任何人**
8. 複製產生的 `/exec` URL 備用（格式：`https://script.google.com/macros/s/{deploymentId}/exec`）

### 第三階段：前端設定

1. Fork / clone 本 repo 到貴單位 GitHub
2. 修改 `js/config.js`：
   ```js
   window.APP_CONFIG = {
     GAS_URL: '貴單位 GAS Web App URL',
     API_TOKEN: '與 GAS 一致的 token',
     TRAINING_UNIT: '貴單位全名',
     TRAINING_UNIT_CODE: '貴單位代碼',
     AUTHORITY: '主管機關名稱',
     CURRENT_ROC_YEAR: new Date().getFullYear() - 1911,
     POST_SUBMIT_REDIRECT_URL: '貴單位 LINE 加好友連結',
     FETCH_TIMEOUT_MS: 20000,
     VERSION: 'YYYYMMDDa',
   };
   ```
3. 修改 `form.html` 的考場下拉選單（依貴單位考場名稱）
4. 修改各頁面 `<title>` 與 header 中的單位名稱
5. 替換 `icons/icon.svg`（貴單位 logo，建議 SVG）

### 第四階段：部署 GitHub Pages

1. Repo Settings → Pages → Source: **GitHub Actions**
2. 確認 `.github/workflows/deploy-pages.yml` 存在
3. Push 到 main 分支會自動部署
4. 等 1-3 分鐘（GitHub Actions 部署需時），到 `https://{你的帳號}.github.io/{repo 名}/` 確認上線

### 第五階段：實機測試

1. 用手機開網址 → 輸入清冊內任一身分證 → 確認能查到
2. 填表 → 拍身分證（建議現場光源充足）→ 預覽 → 送出
3. 到 Drive 報名表收件資料夾確認 PDF 已收到

## 🔬 技術難點與解法

### 1. Android Chrome PDF 跑版
**問題：** 手機窄 viewport 導致表格中文擠成直書

**解法：**
- 把 `#printPage` clone 到固定 720px 寬的隱藏 iframe
- 從 `document.styleSheets` 讀 cssText 直接 inline 注入（不等網路）
- iframe 內注入 `table-layout: fixed`

### 2. 身分證照片方向錯誤
**問題：** 相簿選的照片 EXIF Orientation 沒被自動套用

**解法：**
- `createImageBitmap(file, { imageOrientation: 'from-image' })`
- 不支援的舊瀏覽器：手動 EXIF parser fallback

### 3. 相機拍照框與實際擷取不符
**問題：** 學員在 1.58:1 框內對齊 ID，但擷取時拍下整個畫面

**解法：**
- 根據 video.getBoundingClientRect() + frame.getBoundingClientRect()
- 反算 overlay 在 video 原生座標的範圍 + 15% margin
- 只擷取該範圍

### 4. Service Worker 學員裝置卡舊版
**問題：** PWA cache 老版本

**解法：**
- **完全不用 SW**！GitHub Pages 預設 HTTP cache 10 分鐘已足夠
- HTML 引用 JS/CSS 用 `?v=YYYYMMDD` query string busting
- 升版後學員 ≤ 10 分鐘自動拿到新版
